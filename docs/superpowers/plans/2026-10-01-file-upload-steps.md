# 文件上传步骤优化：project 隔离 + 限额 + 列表复用 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Align iTest file upload steps with CueCast doc — `test_attachments` becomes project-isolated (sha256 dedup within project), default max size 10 MB, new `GET /cases/:id/attachments` lists project attachments for reuse, `StepEditModal` shows the list, `defaultAttachmentResolver` and steps PUT validate project scope.

**Architecture:** Single additive migration adds `project_id` to `test_attachments` and replaces the global unique on `sha256` with `(project_id, sha256)`. Server routes propagate `project_id`; client API adds `attachments.list`; modal adds a project-scoped reuse list. Resolver + steps validation become project-scoped.

**Tech Stack:** Drizzle ORM, Express 5, Zod, vitest + supertest + testcontainers (PostgreSQL), React 18, Tailwind v4 glass-panel utility classes.

```ts
/** 字节数 → 人类可读（1.2 KB / 3.4 MB）。与 iDO 文件大小同口径。 */
export function formatBytes(bytes: number): string {
  if (bytes < 1024) return `${bytes} B`;
  const units = ['KB', 'MB', 'GB'];
  let v = bytes / 1024;
  let i = 0;
  while (v >= 1024 && i < units.length - 1) {
    v /= 1024;
    i++;
  }
  return `${v.toFixed(v >= 10 ? 0 : 1)} ${units[i]}`;
}
```
