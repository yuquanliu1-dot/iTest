### 6. `getModel` from pi-ai

The plan said `getModel(provider, modelId)` from pi-ai. In 0.99.2 the
"static catalog read" function has been moved / renamed:

Source: `apps/api/node_modules/@earendil-works/pi-ai/dist/compat.d.ts`

```ts
/** @deprecated Static catalog read. Use `getBuiltinModel` from "@earendil-works/pi-ai/providers/all" or `Models.getModel()`. */
export declare const getModel: typeof getBuiltinModel;
```

So `import { getModel } from "@earendil-works/pi-ai"` still resolves (via the
compat shim) but is **deprecated**. The new typed function:

```ts
// apps/api/node_modules/@earendil-works/pi-ai/dist/providers/all.d.ts
import type { Model } from "../types.ts";
export declare function getBuiltinModel<
    TProvider extends BuiltinProvider,
    TModelId extends BuiltinChatModelId<TProvider>,
>(
    provider: TProvider,
    modelId: TModelId,
): Model<CatalogApi<(typeof MODELS)[TProvider][TModelId]>>;
```

Import path: `@earendil-works/pi-ai/providers/all` (re-exported by
`@earendil-works/pi-ai` via `compat.d.ts`).

Returns a fully typed `Model<Api>` for that provider/modelId.

Alternative: use `ModelRuntime.getModel(providerId, modelId)` (returns
`Model<Api> | undefined`) — see next item.

### 7. `ModelRuntime` and auth-injection path

Source: `apps/api/node_modules/@earendil-works/pi-coding-agent/dist/core/model-runtime.d.ts`

```ts

    apiKey?: string;
    env?: Record<string, string>;
    minOAuthValidityMs?: number;
}

export declare class ModelRuntime implements Models {
    static create(options?: CreateModelRuntimeOptions): Promise<ModelRuntime>;

    getProviders(): readonly Provider[];
    getProvider(providerId: string): Provider | undefined;
    getModels(providerId?: string): readonly Model<Api>[];
    getModel(providerId: string, modelId: string): Model<Api> | undefined;

    getAuth(providerId: string, overrides?: ModelRuntimeAuthOverrides): Promise<AuthResult | undefined>;
    getAuth(model: AnyModel, overrides?: ModelRuntimeAuthOverrides): Promise<AuthResult | undefined>;

    setRuntimeApiKey(providerId: string, apiKey: string, options?: AuthOperationOptions): Promise<void>;
    removeRuntimeApiKey(providerId: string, options?: AuthOperationOptions): Promise<void>;
    hasConfiguredAuth(providerId: string): boolean;
    isUsingOAuth(providerId: string): boolean;
    isUsingSubscription(providerId: string): boolean;
    listCredentials(options?: AuthOperationOptions): Promise<readonly CredentialInfo[]>;
    getProviderAuthStatus(providerId: string): AuthStatus;

    stream<TApi extends Api>(model: Model<TApi>, context: Context, options?: ModelsApiStreamOptions<TApi>): AssistantMessageEventStream;
    complete<TApi extends Api>(model: Model<TApi>, context: Context, options?: ModelsApiStreamOptions<TApi>): Promise<AssistantMessage>;
    streamSimple(model: Model<Api>, context: Context, options?: ModelsSimpleStreamOptions): AssistantMessageEventStream;
    completeSimple(model: Model<Api>, context: Context, options?: ModelsSimpleStreamOptions): Promise<AssistantMessage>;

    registerNativeProvider(provider: Provider): void;
    registerProvider(providerId: string, config: ProviderConfigInput): void;
    unregisterProvider(providerId: string): void;
}
```

All three plan-candidate mechanisms for API-key injection exist:

1. `ModelRuntimeAuthOverrides` ctor arg shape (per-call `getAuth(providerId, overrides)`).
   Pass `{ apiKey: '...' }` to bypass stored credentials for one request.

2. `readStoredCredential(providerId, authPath?)` — re-exported from
   `@earendil-works/pi-coding-agent` (`dist/index.d.ts` line 4). One-shot read
   from `auth.json` without instantiating a store.

3. `setRuntimeApiKey(providerId, apiKey)` on `ModelRuntime` — persists into
   the runtime credential store (`RuntimeCredentials` overlay over the file
   `auth.json`), without touching the disk copy. See
   `dist/core/runtime-credentials.d.ts`:

   ```ts
   export declare class RuntimeCredentials implements CredentialStore {
       setRuntimeApiKey(providerId: string, apiKey: string): void;
       removeRuntimeApiKey(providerId: string): void;
       hasRuntimeApiKey(providerId: string): boolean;
       ...
   }
   ```

4. `ExtensionAPI.registerProvider(...)` is available but requires running inside
   an extension — not used in this codebase per Task 5 (`modelBridge.ts`).
   Available signature (from `extensions/types.d.ts`):

   ```ts
   registerProvider(provider: Provider): void;
   registerProvider(name: string, config: ProviderConfig): void;
   ```

**Recommended path for Task 5 / Task 7** (programmatic API key per session):
construct `ModelRuntime.create({ authPath: <isolated auth.json> })`, then call
`runtime.setRuntimeApiKey('anthropic', envKey)` (or `getAuth('anthropic', {
apiKey: envKey })` per request). Either works.
