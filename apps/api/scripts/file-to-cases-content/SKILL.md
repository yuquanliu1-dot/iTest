# 需求文档/表格 → 平台测试用例

把用户在对话里上传的 Word(.docx) 需求文档或 Excel(.xlsx) 表格转成平台用例库中的测试用例。
终点是 **stage_case 暂存**（用户在暂存面板勾选落库），不是生成文档。
下文按上传类型标注 **[Word]** / **[Excel]** 路径，未标注的步骤两者一致。

## 第 0 步：定位输入

在最近的用户消息里找 `<uploaded-file name="…" path="…" chars="…"/>` 标签：
- 有 → 校验扩展名（[Word] 须 .docx，[Excel] 须 .xlsx）；不符说明传错了文件，请用户重新上传后重说一次
- 没有 → 请用户用输入框的附件按钮上传 .docx/.xlsx 后重说一次，不要凭空开做

## 第 1 步：结构化解析

[Word] 文档按章节树渐进读取：

```
run_skill_script(skillName="file-to-cases", script="scripts/parse_docx.py", args=["<path>"])
```

先拿 outline（章节骨架/表格形状/stats）。取章节内容：

```
args=["<path>", "--section", "N"]                 # 顶层章节全文（段落+表格）；N 0 起，取 outline 里的 i
args=["<path>", "--section", "N", "--sub", "M"]   # 子章节；M 与 outline 的 subheadings 下标对齐（0 起）
```

[Excel] 表格按 sheet/行段渐进读取：

```
run_skill_script(skillName="file-to-cases", script="scripts/parse_xlsx.py", args=["<path>"])
```

先拿 outline（sheet 清单/行列数/表头预览/合并单元格数）。取 sheet 内容：

```
args=["<path>", "--sheet", "N"]                     # 第 N 个 sheet 的行（0 起，取 outline 里的 i）
args=["<path>", "--sheet", "N", "--rows", "A:B"]    # 第 A..B 行（含端点；行号=Excel 行号 1 起，与返回 rows[].r 对齐）
```

大 sheet 分段取行（`--rows`），天然避开 run_skill_script 的 100KB 输出上限。

解析返回 `ok=false` → 把 error 原因告诉用户并停在那里，不要臆测文档/表格内容。

## 第 2 步：内容识别与确认

[Word] 从章节段落与表格行识别需求条目：需求编号（`REQ-\d+`、`-\d+` 等原样）、模块（所属章节）、
优先级（原文档标注）、验收标准。

[Excel] 先判断表格形态：
1. **需求矩阵**（列含需求描述/验收标准/模块等）：从行识别需求条目——需求编号（原样）、模块、优先级（原表标注）、验收标准。
2. **用例矩阵**（列含用例标题/操作步骤/预期结果等）：说明「表格已是用例，我将按列映射直接入库」，列出识别到的列名与条数请用户确认；列名对不上映射表时逐列询问含义（映射表见 case-mapping.md），确认后直接跳到第 5 步。

（共通）条目分三层标注：**显性**（原文写出）、**隐性**（没写但必须满足，标 `[推断]`/`[假设]`）、
**衍生**（由角色/场景/边界推导，标 `[待确认]`）——层的区分就是「要求的 vs 猜的」，隐性/衍生
条目一并进清单请用户确认，不得静默混入。列出清单（编号 + 一句话）请用户确认范围；用户可剔除/补充。
**未确认前不进入设计。**

## 第 3 步：测试类型建议（用例矩阵跳过本步）

关键词扫描：性能（并发/响应时间/吞吐）、安全（认证/授权/注入/越权）、集成（接口/联动/消息）、
可靠性（重试/超时/降级/故障）、可服务性（日志/监控/配置）。默认功能测试；检测到关键词的
类型建议追加并给一句理由，用户可增删。确认结果记为本次生成范围。

## 第 4 步：设计用例（用例矩阵跳过本步）

必读 `references/design-principles.md`（场景配比与设计方法）。
按功能类型套用特有风险清单：`references/feature-type-checklists.md`（表单/列表/导入导出/
审批等 8 类的高频漏测点；识别类型后照单检查，不适用跳过）。
字段映射与 stage_case 参数规范必读 `references/case-mapping.md`（含 [Excel] 用例矩阵的
列名模糊映射表；用 read_skill 的 file 参数读取，如 `read_skill(skillName="file-to-cases", file="references/case-mapping.md")`）。

## 第 5 步：暂存前自检 + 逐条暂存

**暂存前自检（必做）**：必读 `references/quality-checklist.md`（用 read_skill 的 file 参数读取），
对拟暂存用例逐条核验（具体对象/可观察预期/原值回填/负向不带真实凭据），不合规的修正后再进入暂存；
第 5/6 条的覆盖度与配比统计记下来，收尾时要报。

每条用例调用一次 `stage_case`（localId 每例新生成 UUID）。条数 >20 时**串行分批**：
每批 ≤10 条 stage_case 后继续下一批，不要等待用户逐条确认（暂存面板统一确认）。
禁止试图并行或一轮塞入全部超长内容。

## 第 6 步：收尾

汇总：X 条输入 → Y 条用例（按模块/测试类型分布；[Excel] 多 sheet 时附各 sheet 分布），
提醒用户到暂存面板确认落库；可提示 `export_cases_xmind` 导出。末尾追加自检统计行
（格式见 quality-checklist.md）：需求覆盖 X/Y 条 + 配比 正常/异常/边界/安全 实际占比 vs 目标。

## 核心纪律

- **严禁臆造**：原文与解析结果里没有的不编；解析失败就明说
- [Excel] 日期列可能显示为 Excel 数字序列值（1900 纪元天数，解析器不做换算）——按序列值原样引用或向用户求证，不要猜日期
- [Excel] 合并单元格只有左上角位置有值，其余位置为空——按空值处理，不要脑补填充
- 步骤必须具体到按钮/输入框/取值；预期必须可验证（页面状态/提示文案/数据变化）
- 拿不准的内容标 `[需确认]` 或 `[假设]`，不要静默填充
- 需求编号/优先级等原值原样带入，不做转换
- 一份文件一次流程；用户要调整时改对应的暂存项（stage_case_op）或说明后重做，不重复堆叠
