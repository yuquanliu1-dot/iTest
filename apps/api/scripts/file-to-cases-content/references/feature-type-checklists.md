# 功能类型测试要点清单（feature-type-checklists）

设计用例前先识别每个需求点所属的功能类型，套用对应清单查漏。清单是「这类功能容易怎么坏」的
经验提示，不是每项都必须出用例：不适用的跳过，与业务规则冲突的以业务规则为准；清单之外的业务
特有规则照常补充。

## 表单类（登录/注册/新增/编辑/搜索）

- 输入验证：必填空值与纯空格、长度上下限、格式（邮箱/手机号/URL）、特殊字符与注入串、数值 0/负数/超上限
- 业务规则：唯一性（重名/重复提交）、关联校验（引用对象不存在）、权限（无权角色提交被拒）
- 提交反馈：成功/失败提示明确到字段、失败后已填数据保留、加载中防重复提交

## 列表类（列表/表格/报表）

- 空态与加载态：0 条、无结果、加载中的呈现
- 分页/排序/筛选：多条件组合筛选、筛选重置、页码边界（末页/超界页码）、排序后操作定位不错行
- 数据量：单条、大量数据时分页正常
- 行操作：编辑/删除/详情、危险操作二次确认、操作后列表刷新

## 树形层级类（组织/设备/菜单树）

- 展开与加载：逐级展开、深层节点可达、懒加载节点的子节点正确
- 节点操作：增删改后树刷新、删除有子节点的父节点（级联或明确拒绝）
- 搜索与选中：按名称搜节点、选中态与展开态在刷新后保持

## 导入导出类（批量导入/文件上传/导出）

- 文件边界：空文件/空行、格式错、损坏文件、超大文件
- 数据校验：字段映射（缺列/多列/列序变）、格式与业务规则校验、部分成功部分失败时反馈成功 N 条失败 M 条且失败原因定位到行
- 重复数据：去重/覆盖策略按规则执行
- 导出：大数据量导出、导出内容与页面数据一致

## 审批类（流程/工单/审核）

- 流程控制：正常流转、驳回后退回发起人、跳级/越节点操作被拒
- 审批动作：同意/拒绝/退回/转办各自的权限与状态迁移正确
- 状态管理：非法迁移被拒（已拒绝再审批）、并发审批同一单
- 通知：新申请与审批结果触达对应人

## 权限类（角色/资源/数据权限）

- 功能权限：各角色可见菜单/按钮差异、未授权访问被拦截
- 数据权限：A 角色看不到 B 角色数据；改 URL/直接打接口越权被拒
- 角色管理：绑定/解绑、多角色权限叠加逻辑、权限变更后旧会话不残留旧权限

## 消息通知类

- 触发与时机：什么事件触发、实时/定时、防重复发送
- 接收与展示：未读标记、已读/删除状态、历史消息可查
- 异常：发送失败的重试与记录、无效接收人不阻塞其他消息

## 支付交易类（支付/退款/充值/订购/扣减）

- 金额安全：两位小数精度、0/负数/超大金额、重复提交不重复扣款
- 状态一致性：支付中/成功/失败流转、超时后订单状态、重复回调不产生二次效果
- 对账：支付记录与业务记录一致
