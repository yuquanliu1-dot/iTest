# 暂存前质量自检（quality-checklist）

**stage_case 之前必读并逐条核验**；第 5/6 条的统计结果必须带进收尾汇总。
第 1–4 条对每条用例生效；第 5–6 条仅需求矩阵（走设计流程）时适用，用例矩阵直接映射的可跳过。

## 逐条判据

1. **步骤具体到真实对象**：可操作界面对象（按钮/输入框/菜单项）+ 具体数据值。
   只写「输入用户名」不给值、「点击按钮」不说哪个按钮，不合格——回设计改具体。
2. **预期可观察**：跳转、提示文案、列表变化、数据记录至少其一。
   「系统正常处理」「操作成功」这类不可验证措辞不合格。
3. **原值回填**：需求编号、优先级从源表格/文档原样带入，不转换、不遗漏、不编造。
4. **负向用例不带真实凭据**：错误密码/越权/锁定类用例不得使用系统里真实存在的
   用户名+密码组合（真实凭据会把负向用例「反杀」成通过）；预期必须写明确的失败提示
   （如「提示用户名或密码错误，未进入系统」），不能只写「登录失败」。
5. **需求覆盖度**：已确认的每条需求条目 ≥1 条用例。未覆盖的条目逐条列出并给一句话理由
   （超范围/无法自动化/用户明确放弃），不允许静默漏掉。
6. **配比统计**：统计正常/异常/边界/安全四类实际条数与占比，对照目标
   （~30/40/20/10，见 design-principles.md）。偏差大时补一句原因说明即可，不强改。

## 收尾统计格式

收尾汇总末尾追加一行自检统计（数字按实际填）：

> 自检：需求覆盖 X/Y 条（未覆盖：…，原因…）；配比 正常 a% / 异常 b% / 边界 c% / 安全 d%（目标 ~30/40/20/10）

用例矩阵形态没有需求条目，覆盖项写「不适用（用例矩阵直接映射）」。
