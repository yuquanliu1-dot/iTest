# Excel 表格 → 平台测试用例

把用户在对话里上传的 Excel(.xlsx) 表格转成平台用例库中的测试用例。
终点是 **stage_case 暂存**（用户在暂存面板勾选落库），不是生成文档。

## 第 0 步：定位输入

在最近的用户消息里找 `<uploaded-file name="…" path="…" chars="…"/>` 标签：
- 有 → 校验 path 以 `.xlsx` 结尾（不是则说明传错了文件，请用户重新上传 .xlsx），取 path 进入第 1 步
- 没有 → 请用户用输入框的附件按钮上传 .xlsx 后重说一次，不要凭空开做

## 第 1 步：结构化解析

```
run_skill_script(skillName="xlsx-to-cases", script="scripts/parse_xlsx.py", args=["<path>"])
```

先拿 outline（sheet 清单/行列数/表头预览/合并单元格数）。取 sheet 内容：

```
args=["<path>", "--sheet", "N"]               # 第 N 个 sheet 的行（0 起，取 outline 里的 i）
args=["<path>", "--sheet", "N", "--rows", "A:B"]   # 第 N 个 sheet 的第 A..B 行（含端点；行号=Excel 行号 1 起，与返回 rows[].r 对齐）
```

大 sheet 分段取行（`--rows`），天然避开 run_skill_script 的 100KB 输出上限。
解析返回 `ok=false` → 把 error 原因告诉用户并停在那里，不要臆测表格内容。

## 第 2 步：内容识别与确认

先判断表格形态，两种都要先列出识别结果请用户确认，**未确认前不进入设计**：

1. **需求矩阵**（列含需求描述/验收标准/模块等）：从行识别需求条目——需求编号（原样）、
   模块、优先级（原表标注）、验收标准。列出清单（编号 + 一句话）请用户确认范围。
2. **用例矩阵**（列含用例标题/操作步骤/预期结果等）：说明「表格已是用例，我将按列映射
   直接入库」，列出识别到的列名与条数请用户确认；列名对不上映射表时逐列询问含义。

## 第 3 步：测试类型建议

需求矩阵才需要本步（用例矩阵直接跳到第 5 步）。关键词扫描：性能（并发/响应时间/吞吐）、
安全（认证/授权/注入/越权）、集成（接口/联动/消息）、可靠性（重试/超时/降级/故障）、
可服务性（日志/监控/配置）。默认功能测试；检测到关键词的类型建议追加并给一句理由，
用户可增删。确认结果记为本次生成范围。

## 第 4 步：设计用例（需求矩阵才需要）

必读 `references/design-principles.md`（场景配比与设计方法）。
字段映射与 stage_case 参数规范必读 `references/case-mapping.md`（用 read_skill 的
file 参数读取，如 `read_skill(skillName="xlsx-to-cases", file="references/case-mapping.md")`）。

## 第 5 步：逐条暂存

每条用例调用一次 `stage_case`（localId 每例新生成 UUID）。条数 >20 时**串行分批**：
每批 ≤10 条 stage_case 后继续下一批，不要等待用户逐条确认（暂存面板统一确认）。
禁止试图并行或一轮塞入全部超长内容。

## 第 6 步：收尾

汇总：X 行输入 → Y 条用例（按 sheet/模块/测试类型分布），提醒用户到暂存面板确认落库；
可提示 `export_cases_xmind` 导出。

## 核心纪律

- **严禁臆造**：表格与解析结果里没有的不编；解析失败就明说
- 日期列可能显示为 Excel 数字序列值（1900 纪元天数，解析器不做换算）——按序列值原样引用或向用户求证，不要猜日期
- 合并单元格只有左上角位置有值，其余位置为空——按空值处理，不要脑补填充
- 步骤必须具体到按钮/输入框/取值；预期必须可验证（页面状态/提示文案/数据变化）
- 拿不准的内容标 `[需确认]` 或 `[假设]`，不要静默填充
- 需求编号/优先级等原值原样带入，不做转换
- 一份表格一次流程；用户要调整时改对应的暂存项（stage_case_op）或说明后重做，不重复堆叠
