# Word 测试报告生成（word-test-report）

把测试执行统计写成一份可下载的 Word 文档。核心纪律：**所有数字来自 query_stats 查询结果；报告结构化成 JSON 一次性传给脚本；生成后平台自动出下载卡，无需你做任何文件传输。**

## 工作流

1. **取数**：用 `query_stats` 查询报告所需数据——概览用 `overview`，逐用例统计用 `case_stats`，失败明细用 `failures`，单次计划运行用 `plan_run_detail`。"最近"未指明天数按 7 天。
2. **组织报告 JSON**（schema 见下）：把查询结果整理成报告正文。数字必须与查询结果一致，结论必须能溯源到数据。
3. **生成**：调用
   `run_skill_script(skillName="word-test-report", script="scripts/generate_report.py", args=['<报告 JSON 字符串>'])`
   JSON 作为**单个参数**整体传入（平台直接 argv 传递，不经 shell，无需转义引号）。建议控制在 100KB 以内——超长先精简段落，不要丢数字。
4. **回复用户**：脚本返回「已生成 N 个文件」即说明下载卡已推送给用户，告知文件名即可；不需要也无法自己发文件。

## 报告 JSON schema

```json
{
  "title": "XX 项目测试报告",            // 必填，文档标题
  "period": "2026-10-22 ~ 2026-10-28",  // 可选，副标题（统计区间）
  "sections": [                          // 必填，按顺序渲染
    {
      "heading": "1 概览",               // 可选，章节标题
      "paragraphs": ["近 7 天共执行 42 次…"],  // 可选，段落列表
      "table": {                         // 可选，表格
        "headers": ["用例", "执行", "通过", "失败"],
        "rows": [["登录", "12", "11", "1"]]
      }
    }
  ]
}
```

- `sections` 至少 1 项；每项 `paragraphs` 与 `table` 至少有其一。
- 推荐骨架：1 概览（执行数、通过率口径：passed=一次通过，healed=自愈通过）/ 2 失败清单（表格，含所属版本）/ 3 计划运行状况 / 4 发现与建议。
- 中文字段值原样写，不需要转义。

## 禁止

- 臆造任何统计数字或结论——查询不到的数据就写「无数据」。
- 把原始 query_stats 的 JSON 全量塞进报告——提炼成表格与段落。
- 生成多个版本让用户挑——一份报告一次生成；写错内容改 JSON 重新调用即可（文件名加时间戳，新旧可区分）。
